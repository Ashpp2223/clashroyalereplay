## Clashback 国际服 16.635.8

本机入口由 `scripts/start_clashback_recorder.ps1` 选择 `clashback-160635001` 配置。它使用专用虚拟机 `CR_Clashback_160635001`（`emulator-5576`）和本地资源目录 `.local-runtime/clashback-160635001`。运行时从该目录启动，冻结程序及桥接仍走同一个桌面入口。

Clashback 的 Linux 加载器在虚拟机内使用 Mesa 渲染。桥接在游戏更新线程确认出牌、推进 tick、读回状态和保存快照。渲染和逻辑使用同一局。重开时重建原生进程，再从存档的初始配置和动作恢复。存档保留 v2 格式和构建、控制代码、资源指纹及投影的身份。

牌序校准核对双方四张起手牌与普通待抽牌的顺序。镜像与圣水采集器的待抽位置采用引擎实际发牌结果。


## 下一次升级的最短闭环

1. **固定版本材料。** 保存原 APK、libg、控制模块、素材指纹、规则文件、协议及投影标识的 SHA-256。APK 版本、内容版本、探针版本分别记录。先检查本机已有环境，用明确的设备和工作目录运行。
2. **先证明原生接口。** 在研究侧固定种子，逐项确认创建、首个可操作 tick、暂停、精确步进、双方出牌、非法动作、技能、终局与清理。每个写入都应有执行回执。不要先改前端卡表掩盖引擎缺口。
3. **验证恢复。** 至少比较两次同日志运行、同 tick 两条不同落点分支、快照恢复后同一后缀、进程重启后的日志恢复、终局恢复。过程状态与结果都比较；同一胜负不足以证明一致。
4. **验证目录与画面。** 逐张基础卡、形态和塔兵走原生消耗路径；分别记录技能的覆盖范围。用原生投影点测试记谱器的实际 TypeScript 坐标函数，覆盖不同显示比例与连续播放后的缩放。
5. **导出版本配置。** 让生成器检查报告属于当前 APK、适配器和控制源码未变化，再导出静态配置。规则、卡牌 ID、塔兵、费用和形态掩码来自本版本证据，名称与图片属于展示映射。
6. **通过现有适配边界接入。** 优先保持项目、节点树和动作日志不变。只有现有契约确实无法表达新能力时才扩展。新增协议能力必须同时明确错误与超时语义。
7. **回归并打包验收。** 跑领域测试、桥接测试、前端构建，再冻结桥接和构建桌面程序。用实际交付的 EXE、冻结桥接和内嵌网页重跑桌面闭环。开发模式通过不能代替发行版通过。
8. **记录交付结果。** 写明入口、依赖、二进制和配置摘要、报告位置、已通过范围、失败后修正及仍未验证项。保留失败证据；不把失败截图或旧报告计作本次成功。

## 已踩过的关键问题

- **不能只替换 libg 和函数地址。** 国服塔兵是 `169...`，旧版是 `159...`；原生手牌槽位是牌组条目索引，记谱器槽位是可见手牌位置。适配器必须转换，并检查实际原生发牌结果。
- **能力发现不能沿用旧白名单。** 0.4.0 的精英检查只遍历旧卡表 `forms & 2`，导致实际存在的新精英从未被测试、也没导出。现在从新包 TOML 的 `SPELL_HERO` / `CardForm = HeroForm` 和基础卡 `EvolvedSpells` 关联枚举，并记录这些文件的摘要；原 CSV 中的占位行不代表实际运行配置。新英雄的技能应另外验证，不能仅靠 `form=2` 的出牌回执。
- **先核对用户实际打开的入口。** 本次用户仍在运行已安装的 0.3.12，桌面快捷方式也指向旧文件。交付目录里的 0.4.x 验收通过不等于用户桌面已经更新。核对进程 EXE 路径、文件版本、快捷方式目标和实际目录；改快捷方式不会替换已经打开的窗口。旧快捷方式备份保存在 `.local-runtime/shortcut-backups/`。
- **tick 与出牌边界必须实测。** 本次国服局面初始化在 tick 90；提交一个动作会消耗一次逻辑步进，首个记谱动作记录到 91。初始回放指令里的 `t/t2` 与运行时注入回执的边界不能混用。暂停不能靠输入 JSON 的 `endTick` 实现。
- **方向来自观察账号。** 当前研究固定 viewer `0:2`，owner 1 在下方、owner 0 在上方；画面方向、尺寸和投影每次连接检查。卡牌点击使用当前观测投影，不能沿用原引擎固定矩形。
- **相机状态与战斗状态分开。** 播放会改变缩放；暂停与恢复需等待原生画面更新。投影不进入战斗摘要，画面缓存键包含投影矩形，否则可能显示旧画面并产生错误落点。
- **不能在不确定写入后重发。** 网络超时时，动作可能已经执行。断开并显式恢复确认状态，再继续编辑；不能重新连接后悄悄重试出牌。技能队列必须绑定代际与 tick，换局、恢复和失败时清空。
- **摘要不是全内存证明。** 当前摘要覆盖 tick、胜负、皇冠、双方手牌/圣水、可观测实体及部分运行状态；不等于 RNG、投射物和所有攻击计时器都被记录。恢复后相同后缀的行为比较不可省略，也不要随意更改摘要算法破坏旧节点校验。
- **快照不是磁盘存档。** 当前原生快照池为 32，句柄只在所属进程/局面有效。项目写初始配置与动作；应用重开后重放，不序列化含指针的快照。
- **画面和无画面分别验收。** 独立无画面逻辑可以很快推进，但不代表桌面显示也能同速恢复；两个模式的状态一致性需要实验，不要直接在未知的画面对局中切换。
- **Python 冻结有单独依赖边界。** 研究运行时动态加载 `psutil`；打包环境必须安装它，并作为隐藏导入收集。已有全局 Python 能导入不代表冻结 EXE 能导入。新增动态模块时同步检查依赖。
- **Tauri 握手后的 stdout 会关闭。** 桥接只输出一行握手；研究 CLI 的进度输出要截获，否则真实桌面连接会触发无效句柄错误。命令行直接运行正常不能排除此问题。
- **Windows PowerShell 5.1 的中文脚本需 UTF-8 BOM。** 无 BOM 时中文快捷方式名会被误解码，可能含 `?` 而无法写入。`package_native_desktop.ps1` 保留 BOM；打包后的中文文件名、快捷方式目标和校验文件也要检查。
- **模拟器兼容实验也要固定身份。** 此次 API31 的 ARM64 翻译曾在原包签名路径触发 SIGILL；研究 APK 用已验证的 target SDK/V1 签名兼容变体，libg 保持原字节。它不是原签名 APK 成功运行，也不是通用发行方案。更换签名后检查实际 UID 和 SELinux 分类。
- **版本不匹配必须显式停止。** 保存完整身份；不能把旧存档的引擎身份改成新值，再把重算结果当原局。切回原入口打开旧版本项目；跨规则迁移要另存为明确的新结果。
