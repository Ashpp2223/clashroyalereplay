# 皇室战争复盘器使用说明

0.4.1 国服 38.4.5 本机入口：双击交付目录中的 `皇室战争复盘器-国服38.4.5.lnk`，使用已有研究环境启动。国服新存档默认 **11 级**，普通入口沿用原引擎及 **16 级**。本说明中首次 SDK 安装和资源导入流程适用于普通入口；国服的环境依赖与验收范围见同目录的《国服版本说明》，源码文档见 [国服接入说明](cn-engine-integration.md)。

## 首页、语言和帮助

- 冷启动先显示独立的存档首页，不自动启动引擎或恢复战斗。首页可新建、继续上次复盘、打开其他项目、刷新列表、选择存档目录和设置运行环境。
- 列表只显示通过校验的 `.cr-native-replay.json`，包含项目名、修改时间和节点数量。不读取、转换、展示或修改第一版 `.cr-replay.json`；手动选择不支持的文件会安全拒绝。
- **继续上次复盘** 显式恢复上次项目和所选节点；默认从已保存节点开始，不恢复上次未提交的草稿，也不弹出草稿恢复确认。运行环境未配置时先完成设置，再继续原先的创建或打开操作。
- **返回首页** 先暂停并确认战斗，保存项目元数据并保留草稿 journal，不会隐式创建节点。保存失败时保留工作区和数据，请保持窗口打开并重试；连接异常时先恢复连接。
- 顶部切换 **English / 简体中文** 即时更新界面，本机保留语言偏好。用户项目名称、节点标题、备注和引擎数据不会被翻译。
- **使用说明** 可随时打开。首次自动说明在战斗工作区就绪后显示一次，不会在尚未配置环境时阻塞首页。
- 窗口较小时，文字、牌栏、按钮和竞技场会一起缩放；大窗口沿用原有三栏布局，新增横向空间优先给节点树。缩放后仍可按原位置出牌、拖动节点和用滚轮缩放节点树。

## 安装和首次连接

1. 运行 `皇室战争复盘器_0.4.1_x64-setup.exe`。安装在当前用户下，应用已包含战斗连接服务和视频解码器，不需要另外安装 Python。
2. 创建、打开复盘或进入运行环境设置后，没有模拟器的电脑会显示安装流程。勾选接受 Android SDK 条款后，应用自动开始安装。应用从 Google 官方地址下载固定版本的最小运行组件，核验后安装专用的后台虚拟设备，无需预装 MuMu、Android Studio 或 Python。
3. 首次组件下载约 1.9 GB，安装目录至少留出 28 GB。默认使用当前用户数据目录；中文路径不兼容时，展开 **高级选项**，用 **更改安装位置** 选择可写的英文路径。电脑需要开启处理器虚拟化与 Windows Hypervisor Platform；向导会检查并提示，不会擅自修改系统设置。
4. 点击 **导入战斗资源包**，选择由匹配游戏文件准备的本地 ZIP，导入完成后自动开始连接，并继续原来的创建或打开操作。公开安装包不包含游戏 APK、更新资源或用户账号数据，运行环境下载不会自动取得这些游戏文件。
5. 已有运行环境时，在设置页的 **高级选项** 中用 **选择已有运行环境** 选择含有 `runtime.json` 和 `prepared.json` 的目录。本机现有目录是 `C:\MyProject\皇室战争复盘记谱器\.local-runtime`；请保留其中的虚拟设备磁盘和游戏准备包。首次启动也会尝试识别本机已经准备好的这套环境。
6. 已配置好环境时，无需点击连接按钮。界面自动显示环境识别、资源检查、启动连接的状态；发生错误才显示 **重试**。更新资源包、切换环境和导出诊断都在 **高级选项**。首次准备完成安装校验和游戏初始化；正常退出会保存已初始化的暂停状态，后续优先恢复。安装文件或版本变化时重新完整校验，恢复失败时重新启动游戏。每次连接仍核验实际运行的引擎与战斗资源。成功后显示双方八张牌序、圣水和原生竞技场。版本不匹配时会禁止战斗编辑。界面采用老版记谱器的浅色蓝白风格，战斗画面随可用区域缩放。

## 创建存档与初始配置

- 点击 **新建存档**，填写名称，分别选择双方八张卡、觉醒或精英形态，并用前移/后移按钮调整牌序。第 1～4 张是起手牌，第 5～8 张是待抽牌。
- 开始新建配置时，后台会提前准备战斗连接，选卡可继续操作；确认创建会复用这次连接。取消配置不会创建存档。打开已有存档时，连接完成后会继续显示恢复局面的进度，直到所选节点恢复完成。
- **我方塔楼牌 / 敌方塔楼牌** 可独立选择皇家塔楼公主、加农炮手、飞刀女爵或皇家厨师，不占八张卡组的位置。塔楼的攻击与特殊机制由原生游戏执行；旧存档沿用公主塔。
- 新战斗默认双方卡牌、国王塔和塔楼牌均为 **16 级**。点击 **创建存档并开始** 后，引擎回读确认牌序，再创建项目文件。
- **初始卡组、塔楼牌、牌序、等级和种子只在创建时设置。** 创建后入口变为 **初始配置（只读）**；保存层也会阻止修改同一份存档的初始配置。需要另一个初始局面时，新建存档。
- 没有已有项目时，运行环境就绪后等待用户创建，不会自动生成标准卡组存档。
- 本版本的新存档使用固定种子 41，普通牌序由原生引擎实际发牌校准；镜像或圣水采集器单张固定在第 8 位，同时携带时固定在第 6、8 位。这些特殊位置遵守已验证的原生发牌行为。
- 每方有一个觉醒位、一个精英位、一个万能位：觉醒位仅供觉醒；精英位与万能位可放精英或英雄，万能位也可放觉醒。同一张卡只能选一种形态；特殊位自动分配，与起手牌序独立。觉醒次数和技能冷却继续由原生引擎决定。
- 卡牌库默认先按费用递增，同费用按普通、稀有、史诗、传奇、英雄递增排序。
- 双方牌栏显示实际四张手牌和待抽顺序。卡牌费用在卡图左上角的紫色水滴中显示，牌序编号在右上角；待抽牌不可直接使用。单位仍在场或补牌期间，按引擎实际返回的状态显示。
- 待抽牌和圣水不足的手牌覆盖 50% 黑色半透明遮罩，不能选中；圣水足够时手牌自动恢复正常。可用性按实际圣水计算，界面四舍五入显示“4.0”但尚未达到 4 圣水时仍不可使用。
- 左侧四张手牌使用较大卡图和蓝色边框区域；右侧待抽牌缩小，置于灰色区域并以间隔、竖边分开。保留 1–8 牌序，不增加分组标题或说明文字。
- 圣水槽和卡牌费用角标统一复用旧版的圣水原图。
- 圣水槽中的数值以大号整数和小号一位小数显示。
- 受支持的早期原生项目沿用原来的等级与发牌规则，已有局面不重写。这不表示支持第一版手工局面存档。

## 创建和恢复分支

1. 点击要继续的节点，恢复这个节点的局面并立即继续推演。也可用 **从当前节点创建子节点** 先复制当前局面并选中新子节点，同一时刻也可以复制。
2. 点击敌方或我方手牌，再点击竞技场落点。只有原生引擎确认的出牌或技能进入历史。
3. 点击 **保存当前节点** 或右上角 **保存**，会把进度保存到正在编辑的子节点，不额外增加一层。已经产生后代的历史节点保留；从它继续保存会另建分支。
4. 点击树中的节点恢复该局面并立即继续推演，可以直接出牌或暂停后单步，不必先创建子节点。保存新增进度时保留已有后代。拖动节点调整位置，拖动空白移动视图，滚轮缩放，**适应视图** 查看整棵树。节点位置会保存。

- **节点表示时刻，连线表示两个时刻之间的时间段。** 点击 AB 连线从 A 回放 B 的动作，到 B 核验摘要后进入 B 的节点状态，并从这个局面继续推演；即使 B 没有子节点也继续运行，可出牌、暂停、单步和保存。若 B 有多个子分支，按分叉规则暂停等待选择连线；真正战斗终局时停止。若在到达节点的瞬间主动按下暂停，则保持暂停。
- 小球在当前播放的连线上循环流动，表示这条连线正在播放，不表示实际播放位置；百分比按真实战斗 tick 计算。暂停时小球冻结在当前动画位置，继续时恢复流动；再点正在播放的连线不重头播放，再点暂停的当前连线从暂停位置继续。
- 点击节点会按该节点状态继续自由推演，不会自动执行某个已有子分支的动作；播放、单步、出牌和技能都作用于这次推演。点击连线才是回放已录制的时间段，回放期间手牌和技能只读，历史动作不显示为草稿、不写入草稿日志。若要从时间段中间修改，可用 **从当前节点创建子节点** 保留当前动作前缀，再自由推进、出牌和保存。打开存档先停在保存的节点，点击节点即可继续推演。

- 播放、暂停、变速、前后步进和时间条控制原生时间。暂停立即冻结画面，并在引擎确认后显示当前局面；保存节点后保持暂停。出牌在下一逻辑帧生效，每个逻辑帧为 50 毫秒。
- 技能按钮位于战场右侧空白处：敌方在右上、我方在右下，使用对应的游戏原版技能图标和费用角标。冷却期间显示剩余秒数；不可用时置灰，按钮出现或冷却变化不会缩放战场。
- **前进一步/后退一步先暂停再用，每次为 0.05 秒，与播放倍速无关。** 单步完成后等对应画面显示完，按钮才允许下一次操作，避免连续请求让画面积攒后跳动。后退再前进会恢复已有时间线上的出牌，而不是跳过历史动作。
- **存档** 显示项目名、保存时间和节点数，可选择存档目录、打开项目。仅列出有效的当前原生项目，不展示第一版手工局面存档。
- 每条存档右侧的 **删除** 会先弹出确认框，显示存档名称和文件名；取消不修改文件，确认后删除该存档并刷新列表。存档文件删除不能通过 Ctrl+Z 撤回。
- 战斗名称、节点标题和备注可直接修改，点击 **保存** 写入文件。
- 再次启动先进入首页，点击 **继续上次复盘** 恢复项目及所选节点；新一次打开不带入上次未提交的出牌；需要保留的局面请先保存节点。
- 从已知标准版升级时，程序先核对引擎和重放摘要，再另存“升级副本”。原文件不覆盖；未知引擎版本不自动迁移。

## 中断与诊断

- 画面或连接异常后停止操作，点击 **恢复连接**。应用先恢复已保存节点，再自动恢复本次连接中断前的草稿，不弹出上次会话的缓存提示。
- 桌面失联时，后台会自动暂停战斗。退出应用时会停止它创建的引擎和模拟器进程。
- 用 **导出诊断** 保存版本与运行状态；记录不包含会话口令或项目备注。

## 撤回

- 工作区 **撤回** 按钮或 **Ctrl+Z** 支持节点标题、备注、位置、新建、复制、子树删除，以及当前未提交分支的最后一次已确认原生出牌或技能。
- 输入框内保留正常文本撤回。连续文本输入按一次编辑合并，一次完整拖动只记一次；内存最多保存 100 次操作，项目切换清空，正常保存不清空元数据编辑历史，重启不恢复 Ctrl+Z 历史。
- 播放、暂停、时间浏览、语言切换、帮助、设置和文件浏览不进入撤回历史。已保存并被后代依赖的动作保持不可变；不同决策使用时间回退和平行分支。
- 原生动作撤回先暂停确认，再验证原状态，重放保留动作并复验摘要，成功后同步画面、分支和 journal。失败时恢复原状态；无法确认回滚时冻结交互，保留恢复依据并提示恢复连接。
- 项目存档格式不变，撤回历史不写入项目。journal 在结构事务期间临时保留原项目和已确认摘要，防止项目与 journal 两个原子文件之间的中断造成恢复节点缺失；事务完成后移除该备份。

## 节点回放逻辑修正

点击节点和连线播放到达节点共用继续推演逻辑，可直接出牌、暂停、单步和保存；即使节点已有后代，也不会自动执行后代动作或强制先复制节点，保存的新分支保留已有后代。点击连线先回放已录制的时间段，到终点切回节点并继续演算，只有多个子分支需要暂停选边，真正终局才停止。暂停后选择当前连线不会重头开始。循环小球与真实进度分开，暂停冻结动画位置。回放动作不显示为草稿；撤回从回放帧创建的子节点，也会返回原来的暂停回放。

桥接代码沿用此前已通过 129 项 Python 测试的版本。现有 `scripts/verify_native_frontend.mjs --edge-playback` 通过应用函数和模拟接口验证节点点击与连线到达后继续推演、叶节点后继续运行并单步出牌保存、分叉选边、真正终局停止、延迟响应下的暂停、续播和复制撤回，没有鼠标操作。当前测试结果见 `.local-runtime/native-ux-check/edge-playback-frontend-report.json`。

`scripts/verify_native_deployment.py --restore-only --edge-check` 使用发布目录的桥接程序和独立报告目录，真实国服引擎完成 AB 暂停/变速/续播、AC 接续 CF，终点 tick 与摘要均一致，并读取各终点原生画面。通过报告在 `.local-runtime/edge-playback-flow-snapshots/report.json`。这条路径沿用应用的根节点快照恢复。此前反复重置对局的测试发生过一次 `/v1/reset` 超时，诊断保留在 `.local-runtime/edge-playback-flow-native/report.json`，原因尚未定位，不能据本次快照路径通过声称重置超时已修复。
